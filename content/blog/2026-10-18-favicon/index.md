站点图标决定浏览器标签页与手机主屏上的样子。站点自带一套默认图标，可以换成自己的，换完本地刷新就能看到。

## 生成哪些尺寸

图标按一张源图生成整套尺寸，不需要手工维护多份文件。

| 尺寸 | 用途 |
|---|---|
| 16 与 32 像素 | 浏览器标签页 |
| 180 像素 | 手机主屏 |
| 192 与 512 像素 | 安装到桌面后的图标 |
| 旧格式图标 | 老浏览器与直接访问图标地址 |

尺寸不对时浏览器会缩放，边缘容易发虚。生成结果随构建一起输出，图标属于站点自己的文件，换主题后仍然保留。

## 用后台换 PNG

- 运行 `npm run dev`，打开后台的「主题 → 站点设置」。
- 在「站点图标」里上传 PNG：正方形，宽高偏差不超过 2%，边长 16–512 像素，不超过 256KB。
- 只传标签页图标就够了，触摸图标留空时会沿用同一张；需要单独的主屏图标，再传第二张。
- 保存设置，重启本地开发服务器或重新构建，生成的尺寸才会更新。

后台只在本地开发环境可写，线上是只读页面。

## 用 SVG

SVG 不能在后台上传。把文件放进 `public/`，再在站点设置的图标路径里填写文件名。

<details>
<summary>site.json 的图标路径</summary>

```json
{
  "favicon": {
    "svg": "/<ICON-NAME>.svg",
    "png": "/images/site/<UPLOADED-PNG>",
    "appleTouchIcon": "/images/site/<TOUCH-PNG>"
  }
}
```

</details>

- `<ICON-NAME>` 换成放进 `public/` 的 SVG 文件名，不要带 `public/`。
- 上传 PNG 后后台会自动写入后两项，一般不用手改；清空即回到自带图标。
- 只支持站点自己的文件，不能填外部网址；扩展名必须是 `.svg`。
- SVG 适合几何图形，缩放到标签页尺寸仍然清晰；它只用于浏览器标签页，手机主屏图标仍然用 PNG。

## 没填满时的回退

回退是逐级进行的，只配一部分图标也能正常显示。

- 标签页：设置里填的图标 → 生成的 16 与 32 像素图标 → 自带默认图标。
- 主屏：设置里填的触摸图标 → 标签页图标 → 生成的 180 像素图标 → 自带默认图标。

路径写错或文件放错位置时，页面不会出现裂图，会继续往下找一个能用的图标。

## 换完没生效

- 浏览器缓存可能还留着旧图标，用强制刷新或换无痕窗口再看。
- 确认文件放进了 `public/`，设置里的路径与文件名完全一致。
- 换了源图还要重启本地开发服务器，让生成的尺寸一起更新。

线上四个图标地址都能正常返回、文件本身也没有问题时，标签页仍显示旧图，通常就是缓存或旧标签页。

## 反向代理拦截

站点前面有反向代理、访问控制或人机验证时，图标请求可能被拦成网页。表现是标签页空白，直接用地址打开却能显示图片。

- 让代理放行图标的实际路径，常见的是 `/favicon.ico` 与 `/images/site/` 开头的文件。
- 放行后确认返回的是图片类型，不是登录页或验证页。
- 缓存会让修复后的图标不更新，换无痕窗口再试。

完整规则见[主题设置](https://github.com/planetarium1001/astro-versicarium/blob/main/docs/settings.md)的「站点图标」一节。
