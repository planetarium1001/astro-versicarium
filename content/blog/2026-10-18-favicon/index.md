站点自带一套默认图标，图标由 `DeepSeek V4.1 Flash 1017` 创作，可以换成自己的。图标会出现在浏览器标签页和手机主屏上；换好之后本地刷新就能看到效果。

标签页图标是访问者最先看到的站点标识，主屏图标决定添加到桌面后的样子。两者可以是同一张图，也可以是两张分别设计的图。格式按用途区分：标签页支持 SVG 与 PNG，主屏图标使用 PNG。

图标尺寸不止一种：标签页最小，手机主屏与安装到桌面的图标更大。尺寸不对时浏览器会缩放，边缘容易发虚。站点按一张源图生成整套尺寸，不需要手工维护多份文件。

上传的图标与设置都属于站点自己的文件，主题更新不会覆盖它们。没改过设置时，站点一直使用仓库里自带的图标；想换回来，把设置项清空即可。

## 在后台更换

1. 本地运行 `npm run dev`，打开后台的「主题 → 站点设置」。后台只在本地开发环境可写，线上是只读页面。
2. 在「站点图标」里上传 PNG：建议用正方形，边长 16–512 像素，不超过 256KB。
3. 只传标签页图标就够了；触摸图标留空时会复用它。需要单独的主屏图标，再传第二张。
4. 保存设置，重新打开页面确认。

上传的 PNG 作为标签页图标的源图，构建时按它生成几种尺寸，换图后这些会一起更新：

| 尺寸 | 用途 |
| --- | --- |
| 16 与 32 像素 | 浏览器标签页 |
| 180 像素 | 手机主屏 |
| 192 与 512 像素 | 安装到桌面后的图标 |
| 旧格式图标 | 老浏览器与直接访问 `/favicon.ico` |

生成结果随构建一起输出，不需要手工准备多份图片。图标属于站点自己的文件，换主题后仍然保留。

## 用 SVG

SVG 不能在后台上传。把它放到 `public/`，然后在站点设置里填路径。

```text
/favicon.svg
public/favicon.svg
```

两种写法指向同一个文件。只支持站点自己的文件，不能填外部网址；文件名可以自己取，扩展名必须是 `.svg`。SVG 适合几何图形，缩放到标签页尺寸仍然清晰；它只用于浏览器标签页，手机主屏图标仍然要用 PNG。

## 图标缺失时的回退

浏览器按顺序找图标，找到能用的就停：

1. 设置里填的标签页图标，文件存在时直接使用；
2. 否则用生成好的小尺寸图标；
3. 生成结果也没有时，用站点自带的默认图标。

主屏图标单独一套顺序：设置里填了就用它；没填就沿用标签页图标；再没有就用生成的 180 像素图标；都没有时用自带的主屏图标。回退是逐级进行的，因此只配一部分图标也能正常显示，不会出现空白标签页。路径写错或文件放错位置时，页面不会出现裂图，会继续往下找一个能用的图标。

## 本地验证

换了图标路径后刷新页面即可；换了源图、想让生成的尺寸一起更新时，重启本地开发服务器。确认标签页图标是否更换了。

## 换完没生效的检查

1. 浏览器缓存可能还留着旧图标，用强制刷新或换无痕窗口再看。
2. 确认文件放进了 `public/`，设置里的路径与文件名完全一致。
3. 线上站点还要检查反向代理。

线上四个图标地址都能正常返回、文件本身也没有问题时，标签页仍显示旧图，通常就是缓存或旧标签页。先换无痕窗口复核，再怀疑文件。

## 反向代理

站点前面有反向代理、访问控制或人机验证时，图标请求可能被拦成网页。表现是标签页空白，直接用地址打开却能显示图片。被拦时返回的通常是登录页或验证页，类型不是图片，浏览器就当作图标不可用。

处理办法：让代理放行图标的实际路径，常见的是 `/favicon.ico` 与 `/images/site/` 开头的文件；放行后确认返回的是图片类型，不是网页；缓存会让修复后的图标不更新，换无痕窗口再试。放行后先确认标签页图标恢复，再检查主屏图标。

完整规则见[站点图标](https://github.com/planetarium1001/astro-versicarium/blob/main/docs/favicon.md)。
