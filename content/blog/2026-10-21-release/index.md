主题用版本号标记兼容性，用标签和变更记录留下发布痕迹。版本号回答「能不能直接更新」，标签与 Release 回答「哪一版、什么时候发」，变更记录回答「这一版改了什么」。

发一个新版本要经过提交、发布用的合并请求、GitHub Release 与附件打包几步；模板包从 Release 页面下载。

用主题建站时，通常不需要自己发布。站点关心的是什么时候同步新版本，见[主题更新](/blog/2026-10-15-theme-update/)。

## 版本号、标签与变更记录

版本号采用语义化版本：主版本表示需要重新配置的改动，次版本表示新增功能，修订版本表示修复。主版本变化意味着站点要跟着改配置或内容，次版本与修订版本通常可以直接更新。

面向使用者有三处要同步：

| 位置 | 内容 |
| --- | --- |
| 版本文件 `package.json` | 当前版本号 |
| 版本标签 | `v` 加版本号，例如 `v1.0.0-rc.2` |
| `CHANGELOG.md` | 面向使用者的变更记录 |

预览候选用 `-rc.N` 后缀，表示正式版之前还会调整。常规发布时，发布工具还会同步一份内部版本清单，不需要手动改；预览候选由维护者手动写入。标签与版本号写成同一个值，标签去掉前缀 `v` 后应对应 `package.json` 里的版本号。

版本号里不带日期。日期不说明兼容性，看到日期也判断不了能否与前一版共存；提交时间由 Git 记录。

## 什么时候需要发布

主题本身有对外变化时才需要发布：新增或调整字段、改变公开路由、修复影响使用的问题、更新文档与资源。站点自己的内容增删不需要发版，重新构建即可。发布之后，站点按主题更新流程同步，拿到的就是这一版的主题文件。

## 发布一个新版本

1. 在 `main` 上提交改动并推送。提交信息用 `feat`、`fix` 这类前缀，发布工具据此判断这次改动算新功能还是修复；自动检查要能通过。
2. 等发布工具更新发布用的合并请求，里面会改版本号与 `CHANGELOG.md`。预览候选的版本是手动写入的，不需要这一步。
3. 检查合并请求里的版本号与变更记录，然后合并。
4. 合并后发布工具会创建对应的 GitHub Release，标签与版本号对应。
5. 等自动打包完成，确认 Release 上带着模板压缩包与校验文件。
6. 到示例站同步主题：执行 `npm run theme:update -- --include-fonts`，再执行 `npm run font:build` 重新生成示例站字体。

发布工具负责整理版本号与变更记录，维护者负责检查合并请求与确认 Release。自动检查不通过时，先修 `main` 上的改动，再重新走一遍流程。

## 下载模板包与校验

Release 创建后，页面会提供模板压缩包和校验文件。按版本写入地址，下载并校验：

```bash
VERSION=1.0.0-rc.2
BASE="https://github.com/planetarium1001/astro-versicarium/releases/download/v${VERSION}"
curl -LO "${BASE}/astro-versicarium-${VERSION}.zip"
curl -LO "${BASE}/SHA256SUMS"

sha256sum -c SHA256SUMS
# macOS
shasum -a 256 -c SHA256SUMS
```

校验通过后解压并安装依赖：

```bash
unzip "astro-versicarium-${VERSION}.zip"
cd "astro-versicarium-${VERSION}"
npm ci
```

校验文件列出压缩包的文件名与 SHA-256。下载地址按标签拼出来，正式版把 `VERSION` 换成正式版本号即可。文件名不一致时校验会失败，按版本号重新拼地址下载。校验失败时不要解压使用，重新下载两个文件，确认校验文件里的文件名与下载到的文件名一致。

## 主题基准文件

站点里的主题基准文件 `theme.json` 记录上一次合并到主题的哪个提交。执行一次 `npm run theme:update` 后，它会推进到新的位置，下一次更新从这里继续。

它记录的是提交，不是版本号。同一版本可能对应多次主题更新，版本标签只标记发布节点。`theme.json` 不表示当前安装的版本，也不用手动修改；合并出现冲突时命令不会改它，解决冲突后再跑一次即可。

发布完成后，示例站与自建站点各自执行一次主题更新，拿到新版本的主题文件。站点侧只需要关心主题基准文件推进到了哪个提交。

完整流程见[版本与发布](https://github.com/planetarium1001/astro-versicarium/blob/main/docs/release.md)。
