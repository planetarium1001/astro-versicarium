2026-10-02 12:49，仓库里出现第一条属于我们自己的提交 `5b0914d`。上游是 `cxro/astro-whono`（MIT），首个提交在 2026-01-17，带了双栏壳层、后台控制台、Markdown 管线和字体子集脚本。那天没有动内容结构，只把阅读体验和工程门禁立起来。

文章目录放在宽屏壳层的第 4 列，阅读模式下 1024px 以上展开，窄屏折叠到正文顶部。可以收起，状态记在本地；滚动时高亮当前小节，点目录跳转后目标章节会短暂亮一下。目录一开始就做成壳层的一列，而不是浮在正文右上角的固定块。后者的位置更自由，但开关时会把正文挤来挤去。

右下角加了浮动操作列：阅读模式、回到上次阅读位置、回到顶部。侧栏从 320px 收到 224px，壳层宽度跟着视口走，前后台侧栏内边距统一。主题切换换成以点击处为圆心的圆形展开，系统开了减少动态偏好时直接切换。

同一次提交还塞进两道门禁：首屏 critical CSS 的漂移检查，和 GitHub Pages 的预览工作流。它们跟阅读功能没有直接关系，但后面改内容模型时，至少知道首页样式没有偷偷变形。

第二天 `0a7b5c3`（10-03 00:59）更新 README 并上传了一批截图。10 月 4 日凌晨 `b06c6ae` 补上浏览数据的 PV/UV 槽位和工信部、公安备案信息，还修了一个很烦的 bug：滚动条出现或消失时可用宽度变化，壳层居中跟着挪，整页会横向跳一下。解法是把滚动条槽位固定在 `html` 上，老版 Safari 退化成常驻滚动条才消停。

那批图现在正在重拍。当时用 `npm run dev` 截的，页面底部挂着 Astro 工具栏，比例也不统一，放进文章里一行高度全不一样。单看是小事，积到几十张之后没法维护。现在的规矩是：截图必须来自 `npm run build` 之后的静态服务，宽屏 16:9，亮暗各一份。
