内容放在 `content/`，每条内容是一个目录，正文写在目录里的主文件。文件开头的设置决定标题、日期与是否公开。

## 内容放在哪

`content/` 下分成五个区：

| 分区 | 内容 | 位置 |
| --- | --- | --- |
| 文章 | 长文，可以组成系列 | `content/blog/` |
| 项目 | 项目介绍，可以有多份版本文档 | `content/projects/` |
| 动态 | 短句、图片与随手记录，可以没有标题 | `content/bits/` |
| 开发日志 | 按项目记录的开发进展 | `content/devlog/<项目>/` |
| 关于页 | 固定单页 | `content/about/index.md` |

一个条目一个目录，主文件通常叫 `index.md`，图片和附件放在同级目录。

新建内容有两种方式。一是运行 `npm run dev` 后打开 `/admin/`，进入写作页，选好区再新建，后台会生成目录、主文件与常用设置。二是在对应区里手动建目录和 `index.md`，自己写开头的设置。

目录名会参与默认网址或页内定位，建议写成 `2026-05-01-标题`：日期在前，标题用小写与连字符，中文也可以。动态按日期时间命名，开发日志放在对应项目目录下。

草稿不会出现在线上：开发环境可以看到，构建后的站点、列表与订阅源都会跳过草稿。需要先写好再发布时，把 `draft` 设为 `true`，准备好后再改回 `false`。

正文是普通的 Markdown 文件，不需要经过数据库或额外工具。写完保存，刷新页面就能看到结果；发布则靠重新构建。

## 文件开头的常用设置

| 设置 | 用途 |
| --- | --- |
| `title` | 标题。动态可以不写。 |
| `date` | 日期。写 `2026-05-01` 或 `2026-05-01 09:30`，不要写错格式。 |
| `description` | 一句话摘要，列表与搜索会用到。 |
| `tags` | 标签列表，例如 `[记录, 整理]`。 |
| `draft` | 草稿。写 `true` 时只在本机可见。 |
| `ogImage` | 分享图。写条目内的图片路径或 `https://` 地址；写 `none` 关闭。 |

最小示例：

```markdown
---
title: 一次内容整理
date: 2026-05-01
description: 把旧文章按主题重新归档。
tags: [整理, 记录]
draft: false
ogImage: images/share.webp
---
正文从这里开始。
```

只写日期时页面只显示日期，写了时分则按日期时间显示。示例里的图片路径是示意，换成条目目录里的文件。每个区还有各自的设置：文章和项目的版本号、开发日志对应的项目等。

## 文章系列与项目版本

普通文章不需要额外设置。只有同一篇内容需要保留多次改版时，才用文章系列：

- 每个版本放在自己的目录里，最好分别写上日期；在开头的设置里，给所有版本填同一个 `series` 值。
- 排序时先看日期，日期相同再看版本号 `versionOrder`；排在最前的就是当前版本。
- 旧版本仍可从版本入口查看，页面只显示版本日期。

项目需要多份版本文档时，做法相同：每个版本一个目录，在每份文档里填同一个项目标识，再分别写版本号 `versionLabel` 与版本名称 `versionName`。项目列表只显示最新版，点开卡片可以切换到其他版本。单版本项目不需要这些设置。

## 图片、附件与共享资源

| 放什么 | 怎么放 |
| --- | --- |
| 正文图片 | 放在条目目录里，用相对路径引用，例如 `images/diagram.webp`；放到 `public/` 的图片用 `/` 开头引用 |
| 分享图、项目图标与缩略图 | 条目内的相对路径，或 `https://` 地址 |
| 附件 | 放在条目目录，例如 `files/checklist.pdf`，正文里用普通链接 |
| 多个条目共用的图片 | 放在该区的 `_shared/images/`，例如 `content/blog/_shared/images/` |

附件只在被正文链接时复制到构建结果，没引用的不会上传。共享资源用相对路径从条目引用，例如 `../_shared/images/logo.webp`。图片路径写错时，提交前的检查会报错。

## 正文写法

正文用 Markdown，标题、列表、链接、引用、表格、加粗与斜体都是标准写法。少量 HTML 也能写，但只保留白名单里的标签和属性，脚本会被移除。

提示块有四种类型：`note`、`tip`、`info`、`warning`，方括号里的标题可以省略。

```markdown
:::tip[提示]
这是一段提示。
:::
```

需要图注时写一段 HTML：

```html
<figure class="figure figure--md figure--center">
  <img src="images/diagram.webp" alt="示意图" />
  <figcaption>图注文字</figcaption>
</figure>
```

`figure` 类必须保留。`figure--sm`、`figure--md`、`figure--lg`、`figure--full` 控制宽度，`figure--left`、`figure--center`、`figure--right` 控制位置；不写时居中。多张图并排用 `ul` 加 `gallery` 类，再写 `cols-2` 或 `cols-3` 指定列数。

公式的行内写法是 `$$...$$`，块级公式让 `$$` 单独占一行，单个 `$` 不是公式标记。围栏代码块标上语言，站点会高亮，并显示语言名、行数与复制按钮。折叠内容用 `details` 与 `summary`。

在正文里单独写一行 `<!-- more -->`，它之前的内容会用于列表与卡片的摘要；不写时从全文截取。标记只影响摘要，正文照常显示。

字段全表与扩展写法见[内容与写作](https://github.com/planetarium1001/astro-versicarium/blob/main/docs/writing.md)。
