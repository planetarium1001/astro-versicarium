10-19 的提交是第二次内容模型重构。主题从「能写长文的双栏博客」变成面向多集合与多版本的内容模板，改动集中在内容如何存放、地址如何生成，视觉与阅读交互基本沿用前两版。仓库当时仍以 `astro-whono-tweaked` 发布。

## 内容根与条目目录

内容根从 `src/content/` 移到仓库根的 `content/`，主题代码与作者内容分开。

- `src/` 只放主题代码，`content/` 全部属于作者。
- 主题更新时内容目录不会被覆盖，升级主题也不用迁就 `src/` 的目录结构。
- 一个条目是一个目录，目录里放主文件 `index.md`、图片目录 `images/` 与附件目录 `files/`。
- 目录名即条目 ID，规范写成 `YYYY-MM-DD-title`。

图片与附件跟着条目走，正文用相对路径引用，删除条目时不会留下孤立的图片。条目内也可以放其他素材目录，构建时只复制被正文引用的文件。

README 与文档当时仍是旧目录说明，到 10-22 才重写。

## 五个集合

集合从四个改为五个。

| 集合 | 位置 | 公开地址 |
|---|---|---|
| 文章 | `content/blog/` | `/blog/`、`/blog/<条目>/` |
| 项目 | `content/projects/` | `/projects/` |
| 动态 | `content/bits/` | `/bits/` |
| 开发日志 | `content/devlog/<项目>/` | `/devlog/` |
| 关于 | `content/about/index.md` | `/about/` |

- `essay` 改名为 `blog`，`memo` 删除。
- 列表页有标签筛选与分页，日期按站点时区解析。
- 归档改成跨集合时间线，把文章、项目与开发日志按年月放在一起，动态不进归档。
- 文章列表、标签页与归档从同一份内容读取，草稿只在开发环境可见。

## 文章系列

文章开始支持系列。同一篇内容需要保留多次改版时，各版本放在不同目录，在文件开头填同一个 `series`，再分别写 `versionLabel`、`versionName`、`versionSummary` 与 `versionOrder`。

- 同一系列的版本共用一个 `slug`，最新版占稳定地址，历史版本留在日期地址上。
- 文章页提供版本切换入口，列出每个版本的日期、版本号与版本名称。
- 排序先看日期，日期相同时再看 `versionOrder`，排在最前的是当前版本。
- 历史版本页会标出版本信息，避免与当前版本混淆。

## 项目版本

项目也支持多个版本。

- 同一项目写多个目录，共享项目标识。
- 列表只展示最新版，点开卡片后可以切换到历史版本。
- 每个版本有独立地址，版本号与版本名称写在各自的文件开头。
- 单版本项目不需要这些设置，写一个目录即可，卡片直接指向该版本。

## 后台

开发环境下后台可写。这一版为后台补了版本与文件接口，写作页可以直接创建版本、读取条目内的图片与附件；站点图标可以生成多尺寸产物。

后台分概览、主题、写作、图片与快照五个页面，生产构建仍是只读静态页面，不保留写入能力。主题设置按领域分成多个 JSON 文件，直接编辑文件与通过后台修改等效，字段缺失或非法时回退默认值。

## 主题更新

主题更新在 10-15 先一步落地。仓库里新增 `theme.json`，记录同步到的主题仓库、分支与基准提交。

`npm run theme:update` 拉取新版本后按文件做三方合并：

- 站点未改动的文件直接取新版本。
- 主题未改动的文件保留站点版本。
- 双方都改的文件用 `git merge-file` 合并并列出冲突。

站点自有路径不会被覆盖，合并完成后执行 `npm run verify`。

## 部署

这一版确定双分支模型。

- `main` 是模板分支，只保留最小种子内容与中性默认设置。
- `demo` 是完整示例站，承载 GitHub Pages 部署。
- 主题改动先在 `main` 完成，再同步到 `demo`，方向固定，不反向合并。
- CI 覆盖两个分支，Pages 工作流固定在 `demo` 上构建并发布。

这一版把主题的骨架定了下来：内容根独立、条目目录化、五个集合、系列与项目版本、后台可写、主题更新可用。后续版本不再改内容模型，转向使用体验：改名与品牌资源、窄屏与触屏回归修复，以及字体分层。
