主题更新把主题仓库的新版本合并到站点，只改页面、组件、样式、脚本与默认配置。站点自己的内容、设置、图片、头像与字体保持不动。

主题更新与内容无关，只改内容时不需要执行主题更新，主题仓库有新提交或新版本时再同步即可。

## 更新会改什么

主题负责页面、组件、样式、脚本与默认配置。更新命令会比较三个位置的文件：`theme.json` 记录的基准提交、主题最新提交与站点当前文件；只处理主题负责的文件，站点自有位置直接跳过。

站点自己的文件不会被覆盖：

- 内容：`content/`
- 设置：五个设置文件
- 图片与头像：`public/images/`、`public/author/`
- 字体：`public/fonts/`
- `README.md`、`theme.json`
- 工具清单与生成记录、测试用的页面记录、示例站自动发布配置

想长期保留的定制，放进这些位置或单独的文件。主题负责的文件如果也被站点改过，合并时可能冲突。更新不会改动内容与设置，不需要先备份这些文件；仍然建议先提交，出问题时能回到更新前的状态。

## 普通站点的更新步骤

1. 提交或保存本地改动。工作区有未提交改动时，命令会拒绝执行。
2. 先看清单：`npm run theme:update -- --check`。只列出会新增、更新、删除与冲突的文件，不写盘。
3. 执行 `npm run theme:update`。命令拉取主题最新提交，按文件合并，成功后推进 `theme.json`。
4. 出现冲突时按下一节处理。
5. 报告里「主题已删除」的文件不会自动删除，确认没有用之后再手动删。
6. 运行 `npm run verify`，确认站点正常。

```bash
npm run theme:update -- --check
npm run theme:update
npm run verify
```

清单里的新增、更新、删除与冲突都按文件列出，可以先判断影响范围。`theme.json` 记录上一次合并到的提交，不是版本号，由命令维护。

没有新内容时，命令会提示已是最新，不做任何修改。

## 冲突处理

冲突发生时，命令会把冲突标记写进对应文件，以失败状态结束，并保持 `theme.json` 不变。

- 打开带标记的文件，保留需要的内容，删除冲突标记。
- 不要手工修改 `theme.json`，它由命令维护。
- 解决后重新执行 `npm run theme:update`，让更新继续完成。
- 再运行 `npm run verify`，确认站点正常。

改动较多时，可以在独立分支上执行更新，确认无误后再合并。

## 更新后的检查

`npm run verify` 通过后，再手动确认几处：

- 打开首页与一篇文章，确认样式、字体、图片与目录正常。
- 打开列表页与归档，确认筛选、分页与版本切换可用。
- 进入后台，确认设置页能正常读取和保存。
- 检查本次更新涉及的主题功能，例如导航、阅读模式或浮动操作列。

## 回退

更新结果不符合预期时，用版本控制回到更新前的提交，再重新执行更新。不要手工回滚单个主题文件，容易留下半套改动，后续更新更难合并。

## 示例站与字体

示例站同步时使用 `npm run theme:update -- --include-fonts`，把主题字体一起更新，然后运行 `npm run font:build` 按当前内容重新生成字体。这两个命令只服务示例站，普通站点不需要；普通站点保留自己的字体，避免字体随主题变化。

完整的合并规则见[主题更新](https://github.com/planetarium1001/astro-versicarium/blob/main/docs/upstream.md)。
