站点由两部分组成：内容是作者写的文章、项目、动态与页面，放在 `content/`；主题决定这些内容怎么显示，放在 `src/`。两边分开，升级主题时不会改动内容。

内容都是普通的 Markdown 文件，没有数据库。备份就是复制 `content/`，把整个仓库放进版本控制，改动也有记录。

## 内容与主题

| 部分 | 包含内容 | 位置 |
|---|---|---|
| 内容 | 文章、项目、动态、开发日志、关于页 | `content/` |
| 主题 | 页面、样式、交互与后台 | `src/` |
| 资源 | 字体、图标、头像与图片 | `public/` |

- 只改内容不需要碰 `src/`，改外观也不需要动 `content/`。
- 构建时主题读取内容与设置，生成静态页面。
- 设置文件在 `src/data/settings/`，同样属于站点自己的文件。

## 五个内容区

| 分区 | 位置 | 内容 |
|---|---|---|
| 文章 | `content/blog/` | 有标题、日期、标签的长文，同一主题可以写多个版本 |
| 项目 | `content/projects/` | 项目介绍与各版本的记录 |
| 动态 | `content/bits/` | 短记录，可以带图片和标签 |
| 开发日志 | `content/devlog/<项目>/` | 按项目归档的开发进展 |
| 关于页 | `content/about/index.md` | 固定的单页介绍 |

分区不同，字段也不同：文章要标题与日期，项目要版本号，动态要配图与作者，日志要挂到具体项目上。各自独立成一区，字段才能保持简单。

文章和项目都可以有多个版本。新版本发布后，旧版本保留为历史记录，读者仍能打开，默认看到的是最新版。动态是短记录，不进入归档。

## 一个条目一个目录

每个条目是一个目录，主文件通常叫 `index.md`。为条目新建目录时，把主文件、图片与附件都放在这个目录里。

<details>
<summary>一个文章条目的目录</summary>

```text
content/blog/2026-10-19-example/
  index.md
  images/cover.webp
  files/checklist.pdf
```

</details>

- 目录里只有一个 Markdown 文件时，主文件可以不叫 `index.md`；有多个时给主文件标 `entry: true`，否则构建会报错。
- 正文里的图片用相对路径引用，例如 `images/cover.webp`。
- 条目目录里可以放 `images/`、`files/` 与 `assets/`，分别存图片、附件与素材。
- 多个条目共用的图片放到该内容区的 `_shared/images/`，从条目里按相对路径引用。

图片和附件跟着条目走，删除条目时一起删除，不会留下无主的文件。

## 公开位置

| 分区 | 公开位置 |
|---|---|
| 文章 | `/blog/` 与 `/blog/<条目>/` |
| 项目 | `/projects/`，在弹窗里切换版本 |
| 动态 | `/bits/` |
| 开发日志 | `/devlog/` |
| 关于页 | `/about/` |

## 归档

`/archive/` 把文章的各个版本、项目的各个版本与开发日志放在同一条时间线上，按年月分组。

- 归档有全部、博客、项目、更新四个视图，默认是全部。
- 时间线只显示日期与条目行；博客按系列标签筛选，项目与更新按项目名筛选。
- 归档默认显示所有版本。只想看到每个系列或项目的最新版时，在后台的「内页设置」里切换归档版本。
- 动态不进入归档，它更适合当作时间线上的一句话。

## 七组设置与五个文件

设置分七组，后台主题页按组展示，保存后写入 `src/data/settings/` 下的五个文件。

| 文件 | 内容 |
|---|---|
| `site.json` | 站点设置 |
| `shell.json` | 侧栏设置 |
| `home.json` | 首页设置 |
| `page.json` | 列表页标题、归档版本、分页、订阅源、动态默认作者 |
| `ui.json` | 条目版本、代码显示、排版字体、文章元信息、浮动操作列、浏览数据 |

- 后台保存或直接改文件，刷新页面即生效。
- 换字体是例外，改完要重启 `npm run dev`。

## 后台与线上

后台只在本地开发时可用。运行 `npm run dev` 后打开 `/admin/`，可以改设置、写内容、管理图片与附件。

线上发布的是构建结果，后台只能查看，修改入口都不可用。内容与设置的改动在本地完成，再重新构建发布。

## 主题更新

主题更新使用 `npm run theme:update`。它按文件合并主题的新版本，不会覆盖 `content/`、五个设置文件，也不会覆盖站点自己的图片、头像与字体。

- 更新前先提交本地改动。
- 遇到冲突时手工解决，再重新运行。
- 更新后跑一次 `npm run verify`。

完整的目录表与字段说明见[内容与写作](https://github.com/planetarium1001/astro-versicarium/blob/main/docs/content.md)。
