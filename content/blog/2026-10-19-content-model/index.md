站点由两部分组成：内容是作者写的文章、项目、动态与页面，放在 `content/`；主题决定这些内容怎么显示，放在 `src/`。两边分开，升级主题时不会改动内容。

内容都是普通的 Markdown 文件，没有数据库。备份就是复制 `content/`，把整个仓库放进版本控制，改动也有记录。

## 内容与主题

| 部分 | 包含内容 | 位置 |
| --- | --- | --- |
| 内容 | 文章、项目、动态、开发日志、关于页 | `content/` |
| 主题 | 页面、样式、交互与后台 | `src/` |
| 资源 | 字体、图标、头像与图片 | `public/` |

只改内容不需要碰 `src/`，改外观也不需要动 `content/`。构建时，主题读取内容与设置，生成静态页面。

## 五个内容区

| 分区 | 包含内容 |
| --- | --- |
| 文章 | 有标题、日期、标签的长文，同一主题可以写多个版本 |
| 项目 | 项目介绍与各版本的记录 |
| 动态 | 短记录，可以带图片和标签 |
| 开发日志 | 按项目归档的开发进展 |
| 关于页 | 固定的单页介绍 |

分区不同，字段也不同：文章要标签与摘要，项目要版本号，动态要配图与作者，日志要挂到具体项目上。各自独立成一区，字段才能保持简单。

文章和项目都可以有多个版本。新版本发布后，旧版本保留为历史记录，读者仍能打开，默认看到的是最新版。动态是短记录，不进入归档。

## 一个条目一个目录

每个条目是一个目录，主文件通常叫 `index.md`。为条目新建目录时，把主文件、图片与附件都放在这个目录里：

```text
content/blog/2026-10-19-example/
  index.md
  images/cover.webp
  files/checklist.pdf
```

目录里只有一个 Markdown 文件时，可以省略 `index.md` 直接使用。有 `index.md` 时以它为主文件；没有 `index.md` 又有多个 Markdown 文件时，要给主文件标 `entry: true`，否则构建会报错。

正文里的图片用相对路径引用，例如 `images/cover.webp`。条目目录里可以放 `images/`、`files/` 与 `assets/`，分别存图片、附件与素材。图片和附件跟着条目走，删除条目时一起删除，不会留下无主的文件。多个条目共用的图片放到该内容区的 `_shared/images/`，从条目里按相对路径引用。

## 公开位置

| 分区 | 公开位置 |
| --- | --- |
| 文章 | `/blog/` 与 `/blog/<路径>/` |
| 项目 | `/projects/`，在弹窗里切换版本 |
| 动态 | `/bits/` |
| 开发日志 | `/devlog/` |
| 关于页 | `/about/` |

## 归档

`/archive/` 把文章的各个版本、项目的各个版本与开发日志放在同一条时间线上，按年月分组。归档有全部、文章、项目、日志四个版面，每个版面按时间列出记录，并支持筛选。

归档默认显示所有版本。只想看到每个系列或项目的最新版时，在后台的页面设置里切换。动态不进入归档，它更适合当作时间线上的一句话。

## 后台与线上

后台只在本地开发时可用。运行 `npm run dev` 后打开 `/admin/`，可以改设置、写内容、管理图片与附件。线上发布的是构建结果，后台只能查看，修改入口都不可用。内容与设置的改动在本地完成，再重新构建发布。

## 五组设置

设置分成五组，都是 `src/` 里的文件：

| 分组 | 包含内容 |
| --- | --- |
| 站点 | 标题、描述、语言、时区、页边距、页脚、站点图标与社交链接 |
| 侧栏 | 站点名称、引语与导航顺序 |
| 首页 | 导语、首图与「继续浏览」链接 |
| 页面 | 各列表页的标题、订阅源、分页与归档版本显示 |
| 界面 | 代码块、阅读模式、浮动按钮、字体与统计位置 |

在后台保存后刷新页面生效，直接改文件也一样。字体选择是例外，改完要重启本地开发服务。设置文件也在仓库里，因此改设置和改内容一样，先在本地完成，再构建发布。

## 字体、图标与资源

字体文件、站点图标和头像都在 `public/` 里，构建时随站点一起发布，页面不向外部字体或图标服务请求。站点自带默认图标，可以替换；替换后本地打开页面并强制刷新即可看到。

## 主题更新

主题更新使用 `npm run theme:update`。它按文件合并主题的新版本，不会覆盖 `content/`、五组设置，也不会覆盖站点自己的图片、头像与字体。更新前先提交本地改动；遇到冲突时手工解决，再重新运行。

完整的目录表与设置说明见[站点结构](https://github.com/planetarium1001/astro-versicarium/blob/main/docs/architecture.md)。
