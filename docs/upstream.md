# 主题更新

> 本文档为使用文档，不涉及代码、开发等内容。代码分层、命令参数与实现细节见[开发者文档：与上游的关系](developers/upstream.md)。

主题还在继续改，站点需要定期把新版本合并进来。更新只改主题负责的文件，站点自己的内容、设置与素材保持不动。

方向是单向的：主题仓库改完，示例站和你的站点各自合并过去。上游的改动不会被自动合并，需要手工处理。

## 主题的来源

主题最初来自 [cxro/astro-whono](https://github.com/cxro/astro-whono)，保留 MIT 许可与版权声明。上游是起点，不是本项目的旧版本。

本仓库在这套基础上做了几处调整：

| 部分 | 做法 |
| --- | --- |
| 内容位置 | 作者内容放在 `content/`，主题代码放在 `src/`，两边分开 |
| 内容分区 | 文章、项目、动态、开发日志、关于页五类 |
| 后台 | 本地开发时可以改设置、写内容、管图片；线上只读 |
| 字体 | 按用途切成小份，随站点分发 |
| 发布 | 版本号、标签、变更记录与自动打包 |

## 更新的方向

| 方向 | 方式 |
| --- | --- |
| 上游 → 本仓库 | 手工合并 |
| `main` → 示例站 `demo` | `npm run theme:update`，带字体参数 |
| 主题 → 你的站点 | `npm run theme:update`，按文件合并 |

只朝一个方向走。不要反向合并 `demo` 到 `main`；站点跟踪 `main`，不要直接合并 `demo`。

## 不会被覆盖的文件

下面这些是站点自己的东西，主题更新只把它们列进报告，不会修改：

- 内容：`content/`
- 设置：五个设置文件
- 图片与头像：`public/images/`、`public/author/`
- 字体：`public/fonts/`
- 工具清单与生成记录
- 测试用的页面记录
- `README.md`
- 主题基准文件（`theme.json`）
- 示例站的自动发布配置

想长期保留的定制，放进这些位置或单独的文件里。

示例站同步时会把主题的字体也一起更新；普通站点保留自己的字体。

## 执行一次主题更新

1. 先把正在改的内容提交或保存，确认没有未提交的改动。命令发现未提交改动会直接拒绝执行。
2. 先看会改什么：`npm run theme:update -- --check`。它只列清单，不写文件。
3. 确认后执行 `npm run theme:update`。命令拉取主题最新提交，按文件合并，成功后更新主题基准文件。
4. 出现冲突时，冲突标记会写进对应文件，命令以失败状态结束，主题基准文件保持不变。手动解决标记后重跑。
5. 报告里「主题已删除」的文件不会自动删除，确认没有用之后自己删。
6. 合并完成后运行 `npm run verify`，检查站点是否正常。

没有新内容时，命令会提示已是最新，什么也不做。

## 手工合并上游

只有在维护主题仓库时才需要这一步：

```bash
git remote add upstream https://github.com/cxro/astro-whono.git
git fetch upstream --tags
git checkout main
git merge upstream/main
```

- 冲突时保留本站的内容、设置、图片与主题基准文件。
- 上游的内容字段与页面结构与本站不同时，以本站为准。
- 合并后在 `main` 提交，再到 `demo` 同步一次。
