# 常见问题

## 范围

本篇覆盖：端口、改动不生效、站点地址、图标、构建与检查失败的常见原因。前置：站点能在本地运行，见[安装与运行](install.md)。

## 端口被占用

- 现象：`npm run dev` 提示端口已占用，页面打不开。
- 原因：4321 端口被其他进程占着。
- 做法：换一个端口 `npm run dev -- --port 4322`，或先关掉占用进程。

## 改了设置没生效

- 现象：改完设置刷新页面，内容没变。
- 原因：改的是线上产物，或改动需要重启开发服务器。
- 做法：本地确认后重启 `npm run dev`；线上要重新构建。

## 换了字体没生效

- 现象：换了字体用途，页面还是旧字体。
- 原因：字体在开发服务器启动时读取。
- 做法：重启 `npm run dev`；线上重新构建。

## 没填站点地址

- 现象：分享图、订阅源与站点地图的地址不对，或 `npm run verify` 在产物检查一步失败。
- 原因：没有设置 `SITE_URL`，构建退回占位地址。
- 做法：构建与检查都带上 `SITE_URL=<SITE-URL>`，见[部署上线](deploy.md)。

## Git Bash 改写了子目录路径

- 现象：Windows 下子目录部署的链接多出盘符，或路径被替换。
- 原因：Git Bash 把 `/blog/` 当成文件路径转换。
- 做法：命令前加 `MSYS_NO_PATHCONV=1`。

## 页面能打开但样式丢失

- 现象：页面有内容，样式或图片没有加载。
- 原因：子目录部署漏设子目录，或上传时漏了部分文件。
- 做法：设置 `ASTRO_VERSICARIUM_BASE_PATH` 后重新构建，确认上传的是整个 `dist/`。

## 图标不生效

- 现象：换了图标，标签页还是旧的。
- 原因：浏览器缓存、路径不对，或换了源图没重新生成。
- 做法：强制刷新或换无痕窗口；确认文件在 `public/` 且路径一致；换源图后重启 `npm run dev`。

## 浏览器缓存

- 现象：改了内容或样式，刷新后还是旧的。
- 原因：浏览器或 CDN 缓存保留了旧文件。
- 做法：强制刷新或换无痕窗口；线上在托管平台清缓存后再看。

## 反向代理拦截图标

- 现象：标签页空白，直接打开图标地址却能显示图片。
- 原因：代理、访问控制或人机验证把图标请求当成网页拦截。
- 做法：放行图标路径，常见的是 `/favicon.ico` 与 `/images/site/` 开头的文件，再清缓存。

## 后台保存被拒绝

- 现象：点保存后提示外部更新，或提示配置损坏。
- 原因：设置文件在别处被改过，或文件格式有错。
- 做法：点「重置更改」或「重新检测」，修好文件后再保存。

## 构建失败

- 现象：`npm run build` 报错退出。
- 原因：Node.js 版本过低、依赖没装全，或内容里有构建期错误。
- 做法：确认 Node.js 22.12.0+，用 `npm ci` 重装依赖，按报错定位文件后重跑。

## verify 失败

- 现象：`npm run verify` 中途失败。
- 原因：缺站点地址、页面记录未更新，或产物检查与测试不通过。
- 做法：带上 `SITE_URL` 重跑，按失败步骤的提示修，页面记录有变化时一起提交。
